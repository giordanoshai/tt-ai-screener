# 五个交易分析 skill —— 设计文档

日期：2026-08-29
状态：待评审

---

## 一、要做什么

把这个项目从「10 个通用工具」重做成 **5 个围绕实际交易场景的能力**：

1. **持仓分析** —— 我手上这几只票现在什么情况，该不该动
2. **波段扫描** —— 盘后找值得做的波段机会
3. **个股分析** —— 单独一只票的完整体检
4. **突发消息侦测** —— 出了什么事，跟我有没有关系
5. **持仓盯盘** —— 我的持仓上有没有需要立刻处理的信号

### 形态

每个能力做成**一个 MCP 工具**。工具内部查库、算指标、排序筛选，**返回一份算好的结论**（结构化的精简摘要），Claude 拿到后讲成人话、跟用户对话追问。

工具不调用大模型。原来那种「服务端自己调模型生成报告再返回」的做法取消——慢、烧钱，而且 Claude 变成传话筒，用户想追问得整个重跑一遍。

### 不做什么

明确排除，避免范围蔓延：

- **不做长线**。`screen_stocks`（长线选股）原样保留，这轮不碰。
- **不做前端**。网页面板这轮不改。
- **不做港股**。用户没有港股持仓，要做是独立一轮。
- **不做期权持仓管理**。持仓指股票持仓；期权数据只当判断股票的信号用。
- **不做实时推送、不做回测**。
- **本仓库不写任何采集代码**。这条是硬边界，见第七节。

## 二、总体结构

```
core/                    底层取数模块（新建，可复用）
  snapshot.py            技术面快照：价格、均线关系、RSI、量比、ATR、离20日高多远
  catalyst.py            消息面：重大新闻、财报日、期权异动、内部人买卖
  regime.py              市场环境：大盘状态、涨跌家数、多少票站上均线
  fundamental.py         基本面：只有中线档调用
  cn_signals.py          A 股专用信号：主力资金、龙虎榜、板块轮动、涨停情绪

tools/                   场景工具（MCP 暴露）
  review_positions.py    1 持仓分析
  scan_swing.py          2 波段扫描
  analyze_ticker.py      3 个股分析
  detect_catalysts.py    4 突发消息侦测
  watch_positions.py     5 持仓盯盘
```

为什么分两层：5 个工具里有 4 个要查技术面、3 个要查消息面。各写各的会把同一段查询抄五遍，改一处漏四处。分开之后每块能单独测，以后加第 6 个能力也便宜。

### 数据出入口不变

一切走 `db/pg.py`。四条规矩继续硬性遵守（每一条都真的把这个项目搞崩过一次）：

1. 占位符是 `%s`，不是 `?`
2. 任何行情表查询都要带 `market` 条件
3. 不用相关子查询取最新交易日
4. `stock_fundamentals` 一只票多行，必须 `distinct on (ticker)` 去重

补充第五条（本次新发现）：

5. **`stock_ohlcv_min` 里有三种周期**：`1h`、`1m`、`5m`（美股 5 分钟线 98 万行）。原文档只写了前两种。查询漏掉 `timeframe` 条件会撞上 2000 万行。

## 三、核心：短线用哪些数据，长线用哪些数据

这是整个设计里最要紧的一张表。**红叉的项目在代码里硬性禁止，不是靠自觉**——短波段的评分函数根本拿不到这些字段。

| 数据 | 短波段 3天~2周 | 中线 2周~2月 | 长线（本轮不做） |
|---|---|---|---|
| 20/50 日均线、离均线多远 | 主力 | 用 | — |
| 200 日均线 | 只当大方向参考 | 用 | 核心 |
| RSI（超买超卖） | 用 | 弱参考 | 不用 |
| 量比（今天成交量是平时几倍） | 核心，确认突破真假 | 用 | 不用 |
| ATR（平均真实波幅，用来放止损） | 核心 | 用 | 不用 |
| 20 日 / 55 日新高 | 核心 | 用 | 不用 |
| 期权异动（大额买卖期权） | 核心，看资金往哪押 | 弱参考 | 不用 |
| 隐含波动率排名、相对成交量 | 用 | 参考 | 不用 |
| 期权 gamma 墙（短期压力支撑位） | 用 | 不用 | 不用 |
| 新闻情绪 + 重要性 | 核心 | 用 | 参考 |
| 财报日期 | 核心，用来**避开** | 用，可能是**催化剂** | 用 |
| 市值 / 日均成交额 | 只当流动性门槛 | 用 | 核心 |
| **市盈率、市销率、PEG** | **禁用** | 只当极端值警戒 | 核心 |
| **营收增长、利润增长** | **禁用** | 用 | 核心 |
| **毛利率、ROE、自由现金流** | **禁用** | 参考 | 核心 |
| 分析师目标价 | **禁用** | 用 | 用 |
| 内部人买卖情绪 | 突变时才算信号 | 用 | 用 |
| 做空比例 | 用（有轧空可能） | 用 | 参考 |

一句话：**短波段只看「价格怎么走 + 钱往哪押 + 有没有雷」，公司好不好一概不看**；中线才开始看基本面。

### 落到代码上怎么保证

`core/snapshot.py` 和 `core/fundamental.py` 各自返回不同的数据结构：

- `snapshot.get(tickers, market)` —— 只返回技术面字段，**根本不查 `stock_fundamentals` 的估值和增长列**
- `fundamental.get(tickers, market)` —— 返回基本面，**只被中线档调用**
- 例外：财报日期（`next_earnings_date`）和市值虽然存在 `stock_fundamentals` 里，但短波段需要它们避雷和过流动性。这两个字段单独由 `catalyst.get_earnings()` 和 `snapshot` 的流动性过滤取，**不会顺手把整行基本面带进来**

评分函数按档分开写：`score_short()` 的入参里没有基本面参数，写错了会直接报错，而不是悄悄用上。

## 四、五个工具的规格

### 工具 1：`review_positions` 持仓分析

**参数**：无（可选 `ticker` 过滤单只）

**流程**：
1. 读 `user_positions`
2. 每只票取最新日线（按票 `order by date desc limit 1`，遵守规矩 3，顺带保住停牌退市的票）
3. 算盈亏：现价、盈亏百分比、盈亏金额
4. 技术面：站在 20/50/200 均线上还是下、RSI、量比、ATR 百分比、离 20 日高多远
5. 止损位：取 `成本 - 2×ATR` 和 `20 日均线` 中较高的那个；标注现价有没有跌破
6. 财报：`next_earnings_date` 算还有几天
7. 消息：近 7 天该票的高重要性新闻，最多 3 条
8. 期权资金：近 5 天该票的期权异动，汇总看多溢价和看空溢价（美股才有）
9. A 股换成：近 5 天主力资金净流入、有没有上龙虎榜

**输出（每只票）**：

```
ticker, market, currency, shares, avg_cost, price, pnl_pct, pnl_amount
trend:   {above_ma20, above_ma50, above_ma200, rsi, vol_ratio, atr_pct, dist_from_20d_high_pct}
stop:    {suggested_stop, distance_pct, breached}
earnings:{next_date, days_until}
news:    [{title, sentiment, significance, published_at}]      最多 3 条
flow:    美股 {bullish_premium, bearish_premium, net, alert_count}
         A股  {main_net_5d, lhb_hit, margin_change}
flags:   ["跌破止损", "财报临近", "重大负面消息", ...]
urgency: 0-100
data_gaps: [...]        这只票缺哪几路数据，明写
```

**组合汇总**：按币种分开（`{"USD": {...}, "CNY": {...}}`），**绝不跨币种相加**。附最大单只占比。

**排序**：按紧急度倒序 —— 跌破止损 > 财报 3 天内 > 重大负面消息 > 期权大幅看空 > 正常。

### 工具 2：`scan_swing` 波段扫描

**参数**：`market`（`US`/`CN`）、`horizon`（`short`/`mid`/`both`）、`scope`（`pool` = 持仓+自选 / `full` = 全市场）、`limit`（默认 15，上限 30）

**使用节奏**：每天盘后跑 `scope=pool`；周一、周四盘后跑 `scope=full`。不做盘前扫描——日线和期权异动都是收盘后才灌全的，而且持有周期按周算，不需要抢开盘。

**流动性门槛（先过这道，过不了直接不看）**：
- 美股：市值 ≥ 20 亿美元（用 `ticker_over20b`）且 20 日均额 ≥ 1000 万美元
- A 股：20 日均额 ≥ 5000 万人民币，排除 ST

**短波段形态（三选一，命中才进候选）**：

| 形态 | 条件 |
|---|---|
| 突破 | 收盘 > 前一日的 20 日高点，且量比 ≥ 1.5，且 收盘 > 20 日均线 > 50 日均线 |
| 回踩 | 20 日均线 > 50 日均线，收盘在 20 日均线的 −3% ~ +2% 之间，RSI 在 40~60，且近 20 日内曾创过新高 |
| 超跌反弹 | 收盘 > 200 日均线，RSI < 35，收盘距 50 日均线 < −8%，且近 3 日出现过放量阳线 |

**中线形态**：

| 形态 | 条件 |
|---|---|
| 趋势延续 | 收盘 > 50 日均线 > 200 日均线，50 日均线向上，距 52 周高点 < 15%，且营收增长 > 0、利润率 > 0 |
| 底部反转 | 收盘上穿 200 日均线，200 日均线走平或向上，且基本面没有恶化 |

**排雷**：财报 3 个交易日内的，短波段**直接剔除**；中线**保留但标注**（财报可能正是催化剂）。

**评分（0~100）**：
- 短波段：趋势 30 + 量能 25 + 资金确认 25 + 消息面 20
- 中线：趋势 25 + 基本面 35 + 相对强度 20 + 消息面 20

**输出（每只票）**：

```
ticker, name, market, horizon, setup
price, entry_zone: [low, high], stop, stop_pct, targets: [t1, t2], rr_ratio
score, reasons: [...], risks: [...], data_gaps: [...]
```

止损用 ATR 算（`入场 − 1.5×ATR`），不是拍脑袋定个百分比——不同波动性的票用同一个百分比止损是没有意义的。目标价按 2 倍和 3 倍风险距离给。

### 工具 3：`analyze_ticker` 个股分析

**参数**：`ticker`、`horizon`（默认 `both`）

一份完整体检，把所有能拿到的都拿上：

- 日线趋势（均线、RSI、量比、ATR、52 周位置）
- 小时线买卖点位（**只有该票有小时线数据时才给**；美股目前 196 只、A 股 150 只有）
- 基本面（`horizon` 含 `mid` 时才展开）
- 近 14 天新闻和情绪
- 期权资金流向（近 10 天看多/看空溢价、最大的几笔）
- gamma 墙位置（`uw_gex_daily`，只覆盖约 40 只大盘股，没有就明说）
- 财报日、内部人买卖、国会议员交易
- A 股换成：主力资金 10 日趋势、龙虎榜记录、所属板块近期强弱、融资余额变化

原 `tools/hourly.py` 的小时线逻辑并入这里，不再单独作为一个 MCP 工具。

### 工具 4：`detect_catalysts` 突发消息侦测

**参数**：`scope`（`positions`/`watchlist`/`market`）、`hours`（默认 24）、`min_significance`（默认 `Medium`）

**三路数据合并**：
1. `news` 表 —— 已经有 AI 打好的重要性（High/Medium/Low）和情绪，用 `related_tickers && ARRAY[...]` 匹配
2. `uw_news` —— 带「是否重大」标记
3. **价格自己说的话** —— 该票当日涨跌幅和量比

**最关键的一项判断：股价反应过了没有。**

已经涨完的利好不是机会，是风险。判定：当日涨跌幅绝对值 > 2 倍该票平时波动（用 `atr_pct` 做基准），或量比 > 2，则标记 `reacted = true`。

**输出**：

```
{ticker, event, source, sentiment, significance, published_at,
 price_reaction: {pct_chg, vol_ratio, reacted},
 held: bool, watched: bool}
```

排序：先按是否持有/自选，再按重要性，再按「还没反应」优先。

---

### 工具 5：`watch_positions` 持仓盯盘

**参数**：无（可选 `hours`，默认 24）

只看持仓，四路信号合并：

1. **期权异动** —— `flow_alerts_archive` 近 1~2 天该票的记录。只报**够大的**：单笔溢价 ≥ 50 万美元，或 `score` 进入该票近 30 天的前 10%。A 股换成主力资金异常流出/流入。
2. **突发消息** —— 同工具 4，限定持仓范围
3. **价格触发** —— 跌破 20 日均线、跌破 50 日均线、跌破建议止损位、创 N 日新低
4. **财报临近** —— 5 个交易日内

**输出原则：没事就说没事。**

```
{alerts: [...], checked: 6, message: "6 只持仓，无异常"}
```

不触发就返回空列表加一句话。给一堆看着热闹但不用管的东西，等于没有盯盘——用户会开始忽略它，然后真出事时也忽略了。

每条告警要说清楚三件事：**发生了什么、对我的仓位意味着什么、建议怎么处理**。

## 五、A 股走独立的信号体系

A 股不是「美股那套的残缺版」，而是另一套。原因很直接：A 股个股没有期权，但有美股没有的龙虎榜、主力资金明细和强烈的板块轮动。

### A 股短波段信号

| 信号 | 数据来源 | 作用 |
|---|---|---|
| 均线排列、量比、ATR、20 日新高 | 已有的 `stock_ohlcv_daily` | 趋势和位置，与美股相同 |
| 主力资金净流入（超大单、大单） | 待补：`cn_fund_flow_daily` | **A 股版的「期权异动」**——确认突破是真是假 |
| 龙虎榜 | 待补：`cn_lhb_daily` | 游资进出，A 股短线最强信号之一 |
| 板块轮动强弱 | 待补：`cn_board_*` | A 股是板块市，个股再好逆着板块也难做 |
| 涨停家数、炸板率 | 待补：`cn_limit_pool_daily` | 市场情绪温度，决定今天该不该出手 |
| 个股新闻、业绩预告 | 待补：扩展 `news` + `cn_earnings_forecast` | 催化和避雷 |
| 融资余额变化 | 待补：`cn_margin_daily` | 杠杆资金动向 |

**A 股短波段评分**：趋势 25 + 主力资金 30 + 板块强度 25 + 情绪与消息 20

### A 股中线信号

趋势 + 财务摘要（营收、净利润增长）+ 估值历史分位 + 股东户数变化（筹码在集中还是在分散）。

### 数据没到位之前怎么办

上面标「待补」的表在 `tt-data-hub` 采到之前，A 股扫描**只用已有的技术面**，并且在返回结果的 `data_gaps` 里明写缺哪几项。不静默降级——一个看起来和美股一样、实际少了一半依据的结论，比明说「这里缺数据」危险得多。

## 八、错误处理与降级

三条原则：

1. **任何一路数据缺失都不能让整个工具失败。** 期权异动查不到就是查不到，技术面照样给，缺的写进 `data_gaps`。
2. **缺数据要明写，不静默降级。** A 股查基本面必然为空——不报错，但结果里必须写「A 股无基本面数据」。悄悄返回一个少了一半依据的结论，比返回错误更危险。
3. **检测数据陈旧。** 该市场最新交易日距今超过 3 个交易日，在返回里加陈旧警告，并附上 `ingest_runlog` 里最后一次采集的状态。

## 九、测试

- `core/` 每个模块一个测试，走真实只读连接（现有 `tests/` 已是这个模式）
- 每个工具一个冒烟测试：返回结构完整、不抛异常、美股和 A 股各跑一遍
- **四条查询规矩的回归测试**：扫描 `core/` 和 `tools/` 的 SQL 字符串，检查有没有裸 `?` 占位符、行情表查询有没有带 `market`、有没有相关子查询取最新日期、查 `stock_fundamentals` 有没有 `distinct on`
- 边界用例：空持仓、只有 A 股持仓、某只票停牌（最新日线不是最新交易日）、某只票完全没有新闻
